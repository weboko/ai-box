Is E2B Pro ready to be our sandbox platform?

Eleven things a two-person dev-tools team needs from a sandbox platform, checked one by one against E2B Pro, with Modal and a self-hosted Firecracker fleet as the yardsticks.

The brief takes a minute; the register is for checking.

About this report

Reading the marks

The brief

Verdict · Go, with two exceptions

Yes: E2B Pro is ready for a two-person team today, unless you need GPUs or data residency.

It meets the isolation, session and idle-billing needs, and at 2,000 sandbox-hours a month it costs about $481, against roughly $4.9k for a self-hosted fleet once your time is counted. The first wall will be its 100-sandbox concurrency cap, not price.

    Know this

    1. Self-hosting only wins on hardware. Break-even is ~490 sandbox-hours a month on hardware alone, ~13,000 with 20 ops-hours a month, ~32,000 with a 4-month build.
    2. Hetzner roughly doubled prices for new orders on 15 June 2026, so blog break-evens from before then are stale.
    3. Modal Starter is cheaper below ~2,070 hours a month, but it bills while a sandbox runs and has no pause.
    4. Cold start doesn't decide this. Budget 0.3–0.7 s from create to first command on E2B.

    0.3–0.7 s

    Don't claim

    • “Self-hosting is cheaper above ~500 hours.” True for hardware only; counting your time moves it to 13,000–32,000.
    • “E2B starts in 150 ms.” Measured create-to-first-command is 264–717 ms.
    • “We can run Firecracker on Hetzner Cloud.” It needs /dev/kvm, which Cloud VMs don't document.

    Ask next

    Eleven requirements, one by one

    Five are met outright, two only matter if you need them, and four need watching or a decision.

    ISO

    Strong isolation for untrusted user code

    Each sandbox is a Firecracker microVM with its own kernel.

    Needed
    Agents run code the team didn't write, so a container escape must not reach other tenants.
    Found
    E2B runs every sandbox as a Firecracker microVM, a hardware-virtualisation boundary with the jailer as a second line of defence. Modal defaults to gVisor, a user-space kernel.
    Closes it
    Nothing to do.
    SES

    Sessions long enough for agent runs

    24-hour sessions on Pro; Hobby's 1-hour cap rules it out.

    Needed
    Agent tasks that run for hours without being cut off.
    Found
    Hobby: 1-hour sessions, 20 concurrent. Pro: 24 hours, 100 concurrent, $150 a month.
    Closes it
    Buy Pro, not Hobby.
    IDLE

    Idle time isn't billed

    A paused sandbox costs nothing, as long as the agent actually pauses it.

    Needed
    Agents that wait on people shouldn't burn money while they wait.
    Found
    Paused sandboxes are not billed. A sandbox that computes 10 minutes of each hour but lives the full hour costs six times as much.
    Closes it
    Pause on every wait in the agent loop.
    COST

    Cheaper than self-hosting at our volume

    About $481 a month at 2,000 hours, against about $4.9k all-in for our own fleet.

    Needed
    The lowest total cost at today's volume, counting the team's own time.
    Found
    At 2,000 sandbox-hours, E2B Pro is ~$481 a month; two Hetzner AX42 boxes are ~$230, but all-in self-hosting is ~$4,897. Building the platform is 12–18 engineer-months (a vendor's figure).
    Closes it
    Re-check when spend passes ~$5k a month for three months.
    COLD

    Cold start fast enough for agent UX

    0.3–0.7 s from create to first command: slower than the 150 ms quote, fast enough for agents.

    Needed
    A sandbox ready before the user notices waiting.
    Found
    Measured median 264 ms, p95 603 ms (by a competing vendor), and 717 ms. The 150 ms figure is close to Firecracker's VM boot alone. For agent UX the gap is small.
    Closes it
    Measure from our own region before quoting a number.
    ALT

    The cheapest managed option

    Modal Starter is cheaper below ~2,070 hours a month; at 2,000 the two are within $5.

    Needed
    Not to overpay for the managed route either.
    Found
    Modal costs $0.238 an hour with no plan fee; E2B costs $0.166 plus $150. They cross at ~2,070 hours.
    Closes it
    Pick E2B for pause/resume and microVMs; Modal if GPUs or very low volume matter more.
    CONC

    Headroom for peak concurrency

    Pro stops at 100 concurrent sandboxes; that cap is likely the first wall.

    Needed
    Room for launch-day peaks without changing platform.
    Found
    Pro allows 100 concurrent sandboxes; Modal Starter allows 100 containers. Peak usage is unknown.
    Closes it
    Measure peak concurrency for two weeks, and get E2B's price above 100 in writing.
    EXIT

    A cheap way out

    Lock-in is the SDK and template format; a thin wrapper keeps a switch to days.

    Needed
    Being able to move if prices, limits or the vendor change.
    Found
    E2B's lock-in is its SDK and template format; Modal's is its Python SDK.
    Closes it
    Put sandbox calls behind one interface: create, exec, files, pause, kill.
    PRICE

    Prices that stay put

    No one can promise this; 2026 has already seen two Hetzner increases.

    Found
    Hetzner raised prices twice in 2026. Vendor sandbox rates can move too.
    Closes it
    Re-run this review whenever a vendor reprices.
    GPU

    GPU workloads

    Not offered; only matters if agents need GPUs.

    Found
    E2B doesn't offer GPUs; Hetzner AX boxes have none either. GPUs are Modal's core business.
    Closes it
    If a GPU need appears, run those jobs on Modal behind the same interface.
    RES

    Data residency or bring-your-own-cloud

    Only on Enterprise, from $3,000 a month; only matters if a customer asks.

    Found
    BYOC is an Enterprise feature with a $3,000-a-month minimum.
    Closes it
    Treat the first customer that requires it as a re-evaluation trigger.

    The numbers behind it

    At today's volume the two managed options cost the same, and self-hosting costs ten times more once your time is counted.

    How these were derived

    Reference sandbox 2 vCPU / 4 GiB (an assumption). E2B: 2 × $0.0504 + 4 × $0.0162 = $0.1656 an hour. Self-host: two AX42 boxes at €97.30 plus €49 setup over 24 months, at 1 EUR = 1.16 USD; 14 sandboxes per box; 20 ops-hours and engineering at $100 an hour, 160 hours per engineer-month. All break-evens are estimates from these inputs.

    Next steps

    Buy Pro, wrap it, measure, and set the three triggers that reopen the question.

    1. Start on E2B Pro. It meets ISO, SES, IDLE and COST today; Hobby's 1-hour sessions don't fit.
    2. Wrap sandbox calls behind one interface. Create, exec, files, pause, kill: closes EXIT and makes GPU work on Modal possible later.
    3. Measure two weeks of real use. Sandbox-hours and peak concurrency settle CONC and ALT.
    4. Reopen the decision on any trigger. Spend above ~$5k a month for three months, the 100-sandbox cap, or a customer that needs residency.
    • Concurrency, not price, may force the next decision. Both Pro and Modal Starter stop at 100.
    • The build-effort figure comes from a vendor. No neutral estimate of the 12–18 engineer-months was found.

    Outbox

    Three messages, ready to send as they are.

    Decision: we start on E2B Pro

    I checked E2B Pro against eleven things we need. It's ready for us now: microVM isolation, 24-hour sessions, paused sandboxes aren't billed, and at ~2,000 sandbox-hours it's about $481 a month. Self-hosting only looks cheaper until you count our time; then it's ~$4.9k a month.

    Two gaps only matter if they come up: no GPUs, and data residency only on Enterprise ($3k/month minimum). The real limit is 100 concurrent sandboxes. I'll wrap our calls so we can switch, and measure usage for two weeks.

    Questions before we commit to Pro

    Hi, we're planning to run our agent sandboxes on E2B Pro and have three questions:

    1. What does concurrency above 100 sandboxes cost, short of Enterprise?
    2. Is data residency (EU) or BYOC available below the Enterprise minimum?
    3. Which region should we use for the lowest create-to-first-command time from Europe?

    Thanks!

    Sandbox interface: one seam between our agent and the vendor

    Put every sandbox call behind one interface with five operations: create, exec, files, pause, kill. Pause on every wait in the agent loop. Done when switching the implementation to Modal is a config change plus one adapter.
