Key

TL;DR

Rent (E2B first). Self-hosting only wins on hardware; once your own time is priced in, the break-even moves from ~500 to ~13,000–32,000 sandbox-hours a month.

Two Hetzner AX42 boxes cost about as much as ~490 sandbox-hours/month on E2B Pro. But Firecracker itself is the easy part: networking, snapshots, scheduling and an in-VM agent are 12–18 engineer-months for a production platform, and ops labor dominates below a few thousand sandbox-hours a month. For a two-person team that is the whole company for half a year. Start on E2B (Firecracker isolation, pause/resume) or Modal Starter (cheapest below ~2,070 h/month); keep an exit path; re-check at ~$5k/month of sandbox spend.

Managed Lands

Rent: E2B (Firecracker microVMs) or Modal (gVisor containers). Minutes to first sandbox; the vendor owns the platform.

Three ways to give an agent a disposable Linux box: E2B (Firecracker microVMs), Modal (gVisor containers), or your own Firecracker fleet.

E2B runs each sandbox as a Firecracker microVM with its own kernel. Modal Sandboxes default to gVisor, a user-space kernel that intercepts syscalls; VMs are an alternative. Self-hosting means running Firecracker under its jailer on KVM-capable bare metal.

What the vendor owns for you: control plane, scheduler, template builds, snapshots, networking, observability: the same ground you would survey yourself in the Self-host Frontier.

Isolation

Firecracker: hardware virtualization boundary, jailer as "a second line of defense". gVisor: stronger than namespaces, lighter than a VM. Self-host gets E2B-grade isolation only if you keep seccomp/jailer config tight: "a permanent line item".

Border law: plan limits

E2B Hobby: 1 h sessions, 20 concurrent; Pro: 24 h, 100 concurrent, $150/month; Enterprise $3,000/month minimum, BYOC available. Modal: default sandbox lifetime 5 min, max 24 h; Starter 100 containers, Team 5,000 containers at $250/month.

Firecracker Island

“The easy 5%”: the VMM itself, under jailer on KVM. Security hardening is permanent work.

  • “Firecracker is the easy 5%”: the VMM itself is one small box at the bottom of the stack.
  • Boots “in <125ms” on AWS's tuned path; overhead <5 MiB per VM.
  • Runs under its jailer, “a second line of defense”, on KVM.
  • Security hardening: 1–2 engineer-months, then permanent.
  • Self-hosted cold boot ~1.1 s; snapshot restore ~28 ms, but the warm pool that makes 28 ms possible is one of the 12–18 engineer-month items.

Border A: when does self-hosting pay off?

~400 h/month (hardware) vs “labor dominates”. Reconciled: ~13k–32k h/month once labor is priced.

Side 1 · ~400 h/month

~400 sandbox-hours/month (“roughly one default sandbox running half the day”) on a ~€64 AX52 vs E2B; a companion post puts break-even near two dozen runs a day, using an 8-vCPU/16-GB Hetzner cloud box at ~$19/month and ~$0 marginal cost.

Side 2 · labor dominates

Ops labor is “the dominant line below a few thousand sandbox-hours a month”; building a production platform is “comfortably 12–18 engineer-months” (author sells a sandbox product: conflict of interest).

Reconciliation

  1. Side 1's hardware prices predate Hetzner's 15 June 2026 repricing for new orders: the $19 cloud box (CPX42-class) is now €69.49 and Hetzner Cloud lacks documented KVM anyway. Recomputed with 2 × AX42 at €97.30:

    break-even = (230.47 − 150) / 0.1656 ≈ 486 h/month

    → Side 1's hardware conclusion survives the price hike.
  2. Side 1 prices labor at zero; Side 2 says labor dominates. Adding just 20 h/month at $100/h:

    (2,230.47 − 150) / 0.1656 ≈ 12,560 h → with fleet sizing ≈ 13,260 h/month

  3. Conclusion: Both are right about different cost lines. For a 2-person team, labor is not a rounding error; it is the scarcest input. Self-hosting pays only above roughly 13k–32k sandbox-hours/month, i.e. an E2B bill of ~$2.3k–5.5k/month.

Border B: how fast is a cold start really?

<125 ms claimed vs 264–717 ms measured. Reconciled: budget ~0.3–0.7 s; it does not decide the question.

Claims

Firecracker boots “in <125ms”; E2B is commonly quoted at ~150 ms.

Measurements, create → first command

E2B median 264 ms (p95 603), 717 ms; Modal median 929 ms, 2,437 ms; self-hosted cold boot ~1.1 s, snapshot restore ~28 ms.

Reconciliation

“<125 ms” is VMM-to-guest boot on AWS's tuned path; benchmarks time API call → network → scheduling → first exec, so they must be higher. The 2.7× gap between the two E2B measurements is unexplained (region, client location, method).

Conclusion: budget ~0.3–0.7 s for E2B create-to-first-command; self-host only beats it with a snapshot-restore warm pool (~28 ms restore), which is one of the 12–18 engineer-month items. Cold start does not decide this question.

    Hazards

    Risks and unknowns: price moves, concurrency caps, vendor-sourced effort figures, idle billing.

    • Prices move fast. Hetzner raised twice in 2026; vendor rates may also change.
    • Concurrency limits, not price, may force the decision first (E2B Pro 100; Modal Starter 100).
    • Effort figures are vendor-sourced. Build-effort figures come from a vendor with a conflict of interest; no neutral estimate found.
    • Idle-heavy agents. Billed-hours depend on pausing aggressively; a sandbox that “computes 10 minutes of each hour but lives the full hour costs 6×”.
    • Nested virtualization on Hetzner Cloud. Hetzner Cloud nested virtualization status is undocumented.

    Expedition Plan

    Recommendation and next steps: rent E2B now, keep an exit, re-check at ~$5k/month.

    Recommended route

    1. Now: E2B Pro (or Modal Starter while under ~2,000 h/month and if 24-hour sessions/no-pause are fine). Choose E2B if you need pause/resume or microVM isolation for untrusted user code; Modal if you also need GPUs.
    2. Keep the exit open: wrap sandbox calls behind a thin interface (create / exec / files / pause / kill) so a switch costs days, not months.
    3. Re-evaluate when: sandbox spend passes ~$5k/month for 3 consecutive months, you hit E2B Pro's 100-concurrent cap, or a customer requires data residency / BYOC (E2B Enterprise starts at $3,000/month).
    4. If you do self-host later: dedicated AX servers, not Hetzner Cloud; budget the 8 components, not just Firecracker.

    Next steps

    1. Instrument real sandbox-hours/month and peak concurrency for 2 weeks.
    2. Put those into the calculator; set the $5k/month re-evaluation alert.
    3. Build the sandbox interface wrapper (create/exec/files/pause/kill).
    4. Only if numbers cross break-even: prototype a single-host Firecracker + jailer + snapshot-restore pool on one AX42 to test the 28 ms claim (the Self-host Frontier).
