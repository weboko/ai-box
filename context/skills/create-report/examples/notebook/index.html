Self-host Firecracker on Hetzner, or rent E2B / Modal?

A sandbox decision for a 2-person dev-tools startup: costs, cold starts and the labor nobody prices in. Prices as of 2026-10-18.

TL;DR

Rent (E2B first). Self-hosting only wins on hardware; once your own time is priced in, the break-even moves from ~500 to ~13,000–32,000 sandbox-hours a month.

Two Hetzner AX42 boxes cost about as much as ~490 sandbox-hours/month on E2B Pro. But Firecracker itself is the easy part: networking, snapshots, scheduling and an in-VM agent are 12–18 engineer-months for a production platform, and ops labor dominates below a few thousand sandbox-hours a month. For a two-person team that is the whole company for half a year. Start on E2B (Firecracker isolation, pause/resume) or Modal Starter (cheapest below ~2,070 h/month); keep an exit path; re-check at ~$5k/month of sandbox spend.

Key findings

  1. Hardware math favours self-hosting early. Break-even vs E2B Pro on hardware alone ≈ 490 sandbox-hours/month, consistent with an independent ~400 h/month estimate even after Hetzner's 2026 price rises. → break_even
  2. Labor flips it. Adding 20 ops-hours/month pushes break-even to ~13,260 h/month (~18 sandboxes running 24/7); adding a 4-engineer-month build pushes it to ~32,150 h/month.
  3. Hetzner got ~2× more expensive for new orders on 15 June 2026. AX42-1 is now €97.30/month + €49 setup; cloud CPX42 went €25.49 → €69.49. Blog break-evens using pre-June prices are stale.
  4. Hetzner Cloud VMs are not an option for Firecracker. Firecracker needs /dev/kvm, which requires nested virtualization on cloud VMs; plan on dedicated AX servers, where KVM works. Hetzner does not document nested virt on Cloud.
  5. Cold-start numbers disagree by ~5× (150 ms claimed vs 264–717 ms measured) because they measure different things; for agent UX the gap is small. → Dispute B
  6. Modal vs E2B is a fee-vs-rate trade. Modal costs $0.238/h for 2 vCPU / 4 GiB vs E2B's $0.166/h, but has no plan fee; E2B Hobby's 1-hour session and 20-sandbox caps push real use to Pro at $150/month. Crossover ≈ 2,073 h/month.

Context: what is actually being compared

Three ways to give an agent a disposable Linux box: E2B (Firecracker microVMs), Modal (gVisor containers), or your own Firecracker fleet.

E2B runs each sandbox as a Firecracker microVM with its own kernel. Modal Sandboxes default to gVisor, a user-space kernel that intercepts syscalls; VMs are an alternative. Self-hosting means running Firecracker under its jailer on KVM-capable bare metal.

More: isolation and limits

Isolation

Firecracker: hardware virtualization boundary, jailer as “a second line of defense”. gVisor: stronger than namespaces, lighter than a VM. Self-host gets E2B-grade isolation only if you keep seccomp/jailer config tight, “a permanent line item”.

Limits

E2B Hobby: 1 h sessions, 20 concurrent; Pro: 24 h, 100 concurrent, $150/month; Enterprise $3,000/month minimum, BYOC available. Modal: default sandbox lifetime 5 min, max 24 h; Starter 100 containers, Team 5,000 containers at $250/month.

Dispute A: when does self-hosting pay off?

Claim A1 · hardware

~400 sandbox-hours/month (“roughly one default sandbox running half the day”) on a ~€64 AX52 vs E2B; a companion post puts break-even near two dozen runs a day, using an 8-vCPU/16-GB Hetzner cloud box at ~$19/month and ~$0 marginal cost.

Claim A2 · labor

Ops labor is “the dominant line below a few thousand sandbox-hours a month”; building a production platform is “comfortably 12–18 engineer-months” (the author sells a sandbox product: a conflict of interest).

Best reading: both are right about different cost lines.

For a 2-person team, labor is not a rounding error; it is the scarcest input. Self-hosting pays only above roughly 13k–32k sandbox-hours/month, i.e. an E2B bill of ~$2.3k–5.5k/month (at the report's defaults).

Dispute B: how fast is a cold start really?

Claim B1 · fast

Firecracker boots “in <125ms”; E2B is commonly quoted at ~150 ms.

Claim B2 · measured

Create → first command: E2B median 264 ms / p95 603 ms, Modal 929 / 1,422 ms (Lizard, competing vendor, US East, 300 runs each); E2B 717 ms, Modal 2,437 ms create (LogRocket); self-hosted Firecracker cold boot ~1.1 s, snapshot restore ~28 ms.

claims   = {"firecracker_boot": 125, "e2b_quoted": 150}            # ms [#src-firecracker][#src-softwareseni]
measured = {"e2b_lizard_median": 264, "e2b_logrocket_create": 717}  # ms [#src-lizard-bench][#src-logrocket]
# "<125 ms" is VMM-to-guest boot on AWS's tuned path [#src-firecracker];
# benchmarks time API call → network → scheduling → first exec.
budget  = (min(measured.values()), max(measured.values()))          # 264..717 ms
gap     = 717 / 264                                                 # unexplained

Best reading: budget ~0.3–0.7 s for E2B.

Benchmarks must be higher than the VMM claim because they include the network and scheduling. Self-host only beats it with a snapshot-restore warm pool (~28 ms restore), which is one of the 12–18 eng-month items. Cold start does not decide this question.

Recommendation

  1. Now: E2B Pro (or Modal Starter while under ~2,000 h/month and if 24-hour sessions / no-pause are fine). Choose E2B if you need pause/resume or microVM isolation for untrusted user code; Modal if you also need GPUs.
  2. Keep the exit open: wrap sandbox calls behind a thin interface (create / exec / files / pause / kill) so a switch costs days, not months.
  3. Re-evaluate when: sandbox spend passes ~$5k/month for 3 consecutive months, you hit E2B Pro's 100-concurrent cap, or a customer requires data residency / BYOC (E2B Enterprise starts at $3,000/month).
  4. If you do self-host later: dedicated AX servers, not Hetzner Cloud; budget the 8 components, not just Firecracker.

Risks & unknowns

  • Prices move fast: Hetzner raised twice in 2026; vendor rates may also change.
  • Concurrency limits, not price, may force the decision first (E2B Pro 100; Modal Starter 100).
  • Build-effort figures come from a vendor with a conflict of interest; no neutral estimate found.
  • Idle-heavy agents: billed hours depend on pausing aggressively; a sandbox that “computes 10 minutes of each hour but lives the full hour costs 6×”.
  • Hetzner Cloud nested virtualization status is undocumented.
